# ai_inference_ses：约400 GiB版本

依据SES 1.2.0 PERF_003推理存储带宽模板，采用单个600秒存储访问阶段。
保留80%读、20%写：顺序读40%、顺序写20%、随机读40%，64/128KiB请求各占50%。
SES只提供设计依据，运行直接调用原版Vdbench。

## 逻辑文件和物理分片

| 逻辑文件大小 | 逻辑文件数 | 每块物理分片大小 | 物理文件数 |
|---|---:|---|---:|
| 512MiB | 104 | 128MiB | 416 |
| 1GiB | 139 | 256MiB | 556 |
| 2GiB | 104 | 512MiB | 416 |

共347个逻辑文件、1388个物理文件，总容量399GiB。
每个逻辑文件拆成四个等容量物理分片，四块放在同一桶中；
逻辑文件局部索引j对应物理文件索引4*j至4*j+3。
原版Vdbench要求顺序I/O通道有足够独立文件；四等分使单逻辑文件桶也可承载三个通道。
文件大小类别的请求份额设为约13.0435%、34.7826%、52.1739%，
这些是请求配额，不是文件数量比例。

## 热度和FWD设计

各逻辑文件大小类别内独立计算Zipf(0.99)。85个桶各有顺序读、顺序写和随机读三个FWD，
合计255个FWD；每个通道的64/128KiB混合请求各半。
部分相近排名逻辑文件共用桶，桶内均匀选择分片，近似其逻辑文件访问概率。
这是对逻辑文件的分桶Zipf，不能解释为1388个物理文件各自严格服从全局Zipf。

顺序读、顺序写和随机读是同一阶段内并发的访问通道，不拆成模型加载、prefill或decode阶段。
本负载不执行真实推理，也不模拟KV cache tensor。

容量：399.000000000 GiB；物理文件：1388；最大活跃FWD：255。
默认数据路径：`/mnt/idfs/workloads_400g/ai_inference_ses`。此路径尚未准备，不能把配置存在视为数据已READY。

| 阶段 | 秒 | FWD |

| measure | 600 | 255 |

文件选择Zipf分桶的阶段加权TV误差为0.668037%，最大大小类别条件TV为1.219688%。
这些是概率近似审计，不是识别错误率。

## 配置和入口

- rendered/run_current.vdb：正式配置。
- rendered/run_baseline.vdb：相同阶段和数据布局，组内均匀选择文件的对照。
- rendered/prepare_data.vdb：独立造数据配置。
- rendered/model.json：完整角色、排名范围、配比与来源证据。
- rendered/manifest.json：容量、布局和配置哈希。

本目录render_config.sh仅生成配置，validate_model.sh仅离线验证。
prepare_data.sh和run_test.sh均要求用户授权、--execute和独立的新结果目录。
使用普通Python3与原版Vdbench5.04.07，测量保留模板读写、max、无stopafter。
数据文件需要真实写入，不能用稀疏文件代替。详细命令见[套件README](../README.md)。
