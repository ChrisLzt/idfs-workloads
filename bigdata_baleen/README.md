# Baleen 大数据负载

## 来源

本负载依据[Baleen: ML Admission & Prefetching for Flash Caches（FAST2024）](https://www.usenix.org/conference/fast24/presentation/wong)
及其[官方公开数据集](https://ftp.pdl.cmu.edu/pub/datasets/Baleen24/)。论文附录A.8将Region2列为数据仓库业务。
正式来源为[Region2完整归档](https://ftp.pdl.cmu.edu/pub/datasets/Baleen24/storage_all/storage_all_Region2.tar.gz)
中的`201910/Region2/full.trace`。归档路径标注201910，原始时间戳实际位于2019年9月，均予保留。

原记录给出真实键身份、偏移、请求大小、读写和时间，不含生产数据内容。
本测试提前准备的合成字节是这些访问行为的存储载体，不宣称复制原系统的数据内容或应用计算。

## 全时段整键抽样

在完整约3.983873天时间轴上，固定选择705,130个原始键，保留这些键的全部4,570,814条数据访问记录。
其中GET读取3,925,006次、PUT写入645,808次，请求份额分别约85.87%和14.13%。

选择采用固定seed20261026，对block_id计算SplitMix64哈希，按无符号哈希升序取容器容量不超过5TiB的最长完整键前缀。
选中键约占原始8,190,394个键的8.6092%；优先级不使用访问次数或热度，不逐秒重选键，也不截去其他时段。
抽样会改变相对于完整源的总体比例；“原生冷热”指所选键的原始访问频率没有再被人为重塑。

## 容量与对象布局

| 口径 | 数值 |
|---|---:|
| 4MiB对齐容器容量 | 5,497,553,944,576B，约4.999996TiB |
| 与5TiB预算的差额 | 少4MiB，不另复制数据凑整 |
| 各键最大观测端点之和 | 约4.524374TiB |
| 源请求访问字节并集 | 约4.499951TiB |
| 库存对象位置 | 1,310,719 |
| 源记录实际触达的对象位置 | 1,308,572 |

全部键映射到一个普通容器文件。每键从4MiB边界开始，并独占完整对象区间，保留可逆的key和偏移映射；不混合不同键的尾部。
对象大小和条带单元均为4MiB，stripe_count=1。Region2的原始身份是block_id；映射CSV中的rs_shard_id=0仅为格式兼容占位。

容器映射只平移地址，逐对象触达次数及相交字节分布不变。相对于最大观测端点，对齐预留约0.475622TiB，不参与正式访问。
容器容量、源字节并集和600秒实测覆盖是不同口径，上述对象数是按既定布局映射原记录得到的统计，不是已经在目标集群测得的物理对象库存。

## 冷热与时间设计

不额外设置热点池或施加Zipf。原始记录在4MiB对象布局下，最热20%活跃对象承担约72.31%的读写合并触达次数；
只看读取时约79.64%，写入对象各只写一次，写侧没有明显复用热点。

使用固定的完整源时间边界，将约四天同比例映射为单个600秒RD。
User内部每1秒使用对应源区间的`(offset,size,GET/PUT)`联合频率，600张表均非空。
每秒按原生频率均衡穿插并随机化访问，完整循环保留该片的源频率；切换后不补跑过期片，不逐条复现原始读写顺序。

使用原版Vdbench5.04.06的独立User扩展，保持iorate=max、O_DIRECT，不设逐秒配额；current与baseline使用同一原生方案。
选中请求本来均为4KiB对齐，直接I/O覆盖对齐没有改变这些请求；最大请求44,826,624B，约42.75MiB，跨对象请求仍为一次I/O。
4MiB是对象布局大小，不是单次请求大小。

原始各时间片请求量不同，最大速率下实际完成量也会变化，因此全程频率、实访对象数和有限样本冷热比例仍依赖运行情况。
零地址映射误差不等于零运行误差，不承诺600秒触达全部库存或读取完整5TiB。
