# 图计算：共享边属性文件与对象级Zipf

来源依据为QB认知域作战属性图访问模型：多个客户端共享边属性文件，每次随机读取32字节属性内容，统计10分钟内的存储访问性能。

本负载保留共享大文件、32字节随机纯读和600秒访问窗口，将数据容量设为4TiB，并在全体4MiB对象上添加Zipf(0.99)，用于对象冷热识别和缓存方法比较。容量和Zipf参数为本研究设定，访问由属性读取模型驱动。

| 项目 | 设计 |
|---|---|
| 数据文件 | 一份预先准备好的共享边属性文件 |
| 文件容量 | 4TiB，即4398046511104字节 |
| 对象布局 | object_size=4MiB、stripe_unit=4MiB、stripe_count=1 |
| 配置对象位置 | 1048576 |
| 正式阶段 | 600秒单阶段，100%随机读，每次32字节 |
| 冷热分布 | 全文件对象级Zipf(0.99)，热点在600秒内固定 |
| 多客户端 | 共享同一全局排名和热点映射，各自使用独立随机流 |

每次先按精确离散Zipf抽取对象，再在该对象内均匀选择32字节对齐的起点。访问不跨对象，不单独划分热池，不添加完整扫描或逐秒请求配额。全体库存中最热20%的对象承担约88.13%的理论请求；有限600秒运行的实访对象数和占比仍由实际请求量决定。

4MiB对象布局与造数据时的写入块大小相互独立。数据应提前准备完整，造数据工具、块大小、顺序和并发不属于正式访问模型；原脚本的4MiB顺序写无需复刻，也不混入正式600秒。独立造数入口完成后可等待测试，正式测试不会重新造数。

运行采用原版Vdbench5.04.06＋独立User扩展，使用O_DIRECT和iorate=max。另提供相同文件与请求大小的均匀对象对照，默认只运行Zipf版本。配置和运行说明见[USAGE.md](USAGE.md)。
